# 제작 절차와 확인된 범위

[README로 돌아가기](../README.md)

기록 기준일: 2026-11-09, 한국 시간.

## 목표와 달성 상태

이 도구의 목표는 넓은 한국어 단어 하나에 뭉뚱그려진 뜻을 구별하고, 원문의 형식·사실·말투를 보존하면서 필요한 부분만 교정하는 것입니다.

**도구 제작과 파일 대조는 완료했습니다. 실제 모델의 교정 성능은 아직 검증하지 않았습니다.** 프롬프트가 지시하는 행동과 모델이 실제로 수행한 결과를 구분합니다.

| 항목 | 상태 | 근거 |
| --- | --- | --- |
| 독립적인 원샷 프롬프트 | 제작 완료 | 외부 파일 없이 붙여 넣는 전체 교정 지침 |
| 재사용 가능한 스킬 | 제작 완료 | SKILL.md와 상대 경로 references/rules.json |
| 같은 판단 원칙 | 파일 대조 완료 | 공통 지침·의미 구별 6개·조건부 규칙 16개 |
| 의미 구별·형식 보존·최소 수정 | 설계 검토 완료 | 입력과 기대 출력을 적은 여섯 사례 및 규칙 예시 |
| 표현 목록의 누락 확인 | 자료 대조 완료 | 대표 표현 101개와 추가 표현 62개, 원자료 예문 16개, 초기 스킬 예시 12개 |
| 두 파일을 함께 등록 | 설치기 실행 확인 | Windows PowerShell 5.1·WSL Ubuntu 22.04의 격리된 임시 경로 |
| macOS·Red Hat 계열 실제 설치 | 미확인 | Bash 3.2 호환 문법과 기본 도구로 작성했으나 해당 OS에서 직접 실행하지 않음 |
| 모델이 항상 원칙을 준수하는지 | 미검증 | 모델 교정 과제를 실행한 행동 시험 없음 |
| 교정 개선율·과잉 교정률 | 미측정 | 점수나 개선율을 제시하지 않음 |

## 제작 절차

```text
[User requirements]
         |
         v
[Read supplied research]
         |
         v
[Review 16 conditional rules]
         |
         v
[Write shared editing policy]
         |
         +--> one-shot-prompt.txt
         |
         `--> SKILL.md + rules.json
                    |
                    v
          [Compare rules and examples]
                    |
                    v
          [Package installers and docs]
```

1. 제공된 조사 자료의 근거 성격과 한계를 읽었습니다. 실사용 경험, 표현 목록, 패러디, 편집 조언, 반례를 구별했습니다.
2. 사용자 요구인 의미·형식 보존을 우선해 원본 규칙 16개를 검토했습니다.
3. 공통 정책을 원샷과 스킬에 반영하고, 서로 모순되는 조건이 없는지 대조했습니다.
4. 같은 넓은 말이 서로 다른 뜻을 나타내는 경우, 정확해서 유지할 경우, 근거가 부족한 경우의 예시를 작성했습니다.
5. MD의 표현 색인과 본문·규칙의 추가 항목을 대조해 [191행 표](expression-change-table.md)로 정리했습니다.
6. 스킬 이름을 `natural-korean`으로 통일하고 두 파일을 함께 복사하도록 설치기를 수정했습니다.

조사 자료는 관찰과 편집 제안입니다. 최신 모델의 출력 빈도나 교정 효과를 검증한 실험으로 해석하지 않았습니다. 의미 구별과 엄격한 형식 보존은 이번 도구의 설계 요구입니다. 관련 출처 식별자와 한계는 [rules.json](../skills/natural-korean/references/rules.json)의 `research_context`에 있습니다.

## 원본 규칙 16개의 처리

| 처리 | 규칙 | 반영 방식 |
| --- | --- | --- |
| 삭제·변환 동작 비활성화 5개 | R01 칭찬, R02 감정·성장, R11 후속 제안, R13 서식, R16 교훈형 결말 | 원문에 이미 있는 문장·형식을 보존 |
| 목적에 맞게 조정 9개 | R03·R04·R05·R06·R07·R10·R12·R14·R15 | 문장 내부의 최소 교정으로 한정하고 유지 조건 명시 |
| 유지 2개 | R08 목적어·동사, R09 불필요한 피동 중첩 | 뜻·시제·행위자를 보존하는 조건에서 교정 |

비활성화는 해당 유형의 모든 교정을 막는다는 뜻이 아닙니다. 예를 들어 칭찬 문장을 삭제하는 동작은 막지만, 그 안의 명백한 띄어쓰기 오류는 교정할 수 있습니다.

## 파일 검토

- YAML frontmatter의 이름·설명과 스킬의 상대 참조 경로를 확인했습니다.
- JSON 구문, 원본 규칙 식별자 16개, 출처·분류 참조를 확인했습니다.
- 원샷과 스킬의 공통 지침·적용 조건·유지 조건을 대조했습니다.
- 설계 예시에서 줄바꿈·빈 줄·들여쓰기·마크다운·표·코드·URL·직접 인용이 유지되는지 확인했습니다.
- 스킬은 `automatic_global_replacement: false`, `effectiveness_verified: false`를 명시합니다.

파일 대조는 문법·누락·서식의 문제를 찾는 검사입니다. 실제 모델의 판단을 대신 검증하지는 않습니다. [검수용 사례 6개](design-review-cases.md)는 실행 결과가 아니라 기대 결과를 적은 설계 사례입니다.

## 설치기 확인

수정한 설치기를 **실제 사용자 설치 폴더 대신 작업용 임시 경로**에서 실행했습니다. Windows PowerShell 5.1과 WSL Ubuntu 22.04 Bash 각각에서 다음 여덟 경우를 확인했습니다. 합계 16개 확인 항목을 통과했습니다.

| 확인 항목 | 결과 |
| --- | --- |
| 공백이 있는 경로에 두 도구의 파일 두 개씩 신규 복사 | 원본과 바이트 일치 |
| 같은 파일로 다시 실행 | 파일 내용·수정 시각 유지, 불필요한 백업 없음 |
| 예전 SKILL.md 한 파일 버전에서 업데이트 | 기존 파일 백업, rules.json 추가, 사용자 추가 파일 유지 |
| 두 파일을 모두 수정한 설치본 업데이트 | 두 파일 각각의 기존 내용 백업 |
| Codex만 선택 | Codex 파일만 복사 |
| 원본에 rules.json 누락 | 설치 대상 생성 전에 오류로 중단 |
| references 자리에 일반 파일이 존재 | 기존 파일을 바꾸지 않고 중단 |
| 잘못된 도구 이름 지정 | 파일을 쓰기 전에 오류로 중단 |

Windows 실행 중 파일 해시 명령을 찾지 못하는 환경을 확인해, 추가 PowerShell 모듈 없이 .NET의 파일·해시 기능으로 비교하도록 수정했습니다. macOS의 Bash 3.2 및 Red Hat 계열에서의 직접 실행은 아직 확인하지 않았습니다.

HTML 표는 내용·행 수·문서 링크를 파일 수준에서 확인했습니다. 브라우저에서 표시·검색 기능을 실행해 검증한 결과는 아닙니다.

## 초기 버전과 달라진 점

이름은 `natural-korean`으로 유지합니다. 초기 버전의 새 글 작성·문장 합치기·구성 조절 기능은 이번 교정 범위에 포함하지 않습니다. 원문 형식과 내용 보존을 우선합니다.

스킬은 이제 `SKILL.md`와 `references/rules.json`을 함께 사용합니다. 기존 설치본을 갱신하려면 최신 저장소를 받은 뒤 설치기를 다시 실행합니다. [업데이트와 복구 안내](installation.md#업데이트와-복구)

## 규칙을 수정하거나 기여할 때

1. 바꾸려는 실제 문장과 제공된 문맥을 적습니다. 공개할 예시에서는 개인정보를 제거합니다.
2. 잘못된 부분, 기대 출력, 그대로 보존해야 할 부분을 구분합니다.
3. [rules.json](../skills/natural-korean/references/rules.json)을 수정했다면 [원샷 프롬프트](../one-shot-prompt.txt)의 같은 지침도 수정합니다. 핵심 정책이 바뀌면 SKILL.md도 함께 맞춥니다.
4. 자동 치환·근거 없는 구체화·문장 삭제·서식 변경이 새로 생기지 않았는지 검토합니다.
5. 실제 모델에 실행했다면 모델·버전·입력·출력을 기록합니다. 기대 출력만 만든 경우에는 설계 예시라고 표시합니다.

코드를 내려받아 수정한 뒤에는 변경 파일을 확인하고 관련 파일만 커밋합니다.

```bash
git diff
git add README.md one-shot-prompt.txt skills/natural-korean/SKILL.md skills/natural-korean/references/rules.json
git commit -m "Refine Korean copyediting rules"
git push origin main
```

설치기나 문서를 수정했다면 해당 파일도 명시적으로 추가하세요. 저장소에 쓰기 권한이 없는 사용자는 자신의 Fork에 변경을 올린 뒤 Pull Request로 제안할 수 있습니다.
